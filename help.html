Help Guide

Audit Centre documentation and user guide

Overview

The Audit Centre is a device audit and compliance management platform. It allows organisations to track device inventories, conduct operational audits, manage remediation actions, and maintain compliance records.

Getting Started

Logging In

Sign in with your organisation credentials:

  • Your administrator will provide your username and password
  • All users log in at the same URL — data is isolated per organisation
  • You will only see your organisation's sites and data

Dashboard

The main dashboard shows Registered Devices, Active Sites, Audit Batches, and Open Remediations.

New Client Setup

1. Create the organisation (tenant)

Tenants are separate organisations — each has its own users, sites and audit data.

  • Open Tenant Management (tenant-admin.html)
  • Click + New Tenant
  • Enter the organisation name (e.g. Benowa ELC) and a slug (e.g. benowa-elc)
  • Click Create
  • Select the new tenant and add its users (+ Add User) with their roles

2. Create the client's site

  • Open Site Onboarding (site-onboarding.html)
  • Click + New Site, enter the site name and company, then Create Site
  • The site immediately appears in the list — complete the site's details (rooms, policy checklists) as required

3. Add platform users for the client

  • Open User Management (admin-users.html)
  • Pick the client's tenant from the dropdown, then + New User
  • Enter username, full name, email (for notifications) and password (min 8 chars), choose a role
  • The client's staff log in at the same URL — they only see their own tenant's data

SharePoint / Microsoft Setup (auto-upload audit reports)

Audit reports can be uploaded automatically to the client's SharePoint document library via a Microsoft Graph app. This needs one Azure app registration in the client's Microsoft tenant, then configuration on each site.

Part A — Microsoft side (once per client, needs consent in the client tenant)

  1. Go to entra.microsoft.com and open App registrations → New registration — make sure you are in the client's tenant (the one that holds their SharePoint)
  2. Name it e.g. SimplyICT Audit Upload. Accounts in this organisational directory only. No redirect URI needed. Register
  3. Copy from the app's Overview page:
    • Directory (tenant) ID — the Tenant ID
    • Application (client) ID — the Client ID
  4. Open Certificates & secrets → New client secret (max 24 months — diarise the expiry; expired secrets stop uploads silently). Copy the Value immediately — it is only shown once. This is the Client Secret
  5. Open API permissions → Add a permission → Microsoft Graph → Application permissions and add Sites.ReadWrite.All
  6. Click Grant admin consent for the client tenant — without this, authentication succeeds but SharePoint calls return 403
  7. Note the target site URL, e.g. clientname.sharepoint.com/sites/Audits (the site must already exist)

Part B — Audit Centre side (per site, in Site Onboarding)

  1. Open Site Onboarding and select the site
  2. In the SharePoint Integration block, turn Enable SharePoint Upload on
  3. Fill in:
    • Tenant ID — directory (tenant) ID from Part A step 3
    • Client ID — application (client) ID from Part A step 3
    • Client Secret — the secret value from Part A step 4
    • SharePoint Site URL — e.g. clientname.sharepoint.com/sites/Audits
    • Drive ID — leave blank and click Auto-Discover (uses the default document library)
    • Upload Folder — e.g. Audit Reports/2026 (created automatically; blank = library root)
  4. Save the site, then click Test Connection

Test Connection results

The test runs a four-stage chain: auth → site → drive → folder. The result shows which stage failed.

  • Auth failed — Tenant ID / Client ID / Client Secret wrong, or the secret has expired
  • Auth OK but site not resolved — missing Sites.ReadWrite.All admin consent, or the site URL is wrong
  • Site OK but drive not resolved — the site has no accessible document library
  • Drive OK but folder not accessible — permission/consent issue — re-check admin consent

When the test passes, each finalised audit report is uploaded to that folder automatically.

Audit Schedule

Where it is

Home → Audit Operations → Audit Schedule. The dashboard tiles Next Audit and Overdue Audits both link straight to it.

Reading the calendar

  • Fill colour = the centre (each centre has its own colour, set per site)
  • Left bar + icon = status: ✓ completed, ● due, ⚠ overdue
  • Use ‹ Prev / Today / Next › to move between months
  • Completed entries come from real audits; due entries are projected from each site's cadence

Next Audits table

Shows cadence, last audit, next due date, days remaining and status for every site. Edit sets the cadence (monthly/quarterly/etc.), the preferred day (e.g. Saturday), a manual next-audit override, whether it appears on the calendar, and the centre's colour. Start audit opens the audit page with that site already selected.

How the next date is worked out

Next due = last completed audit + frequency, moved to the site's preferred weekday and kept inside that month, so each centre appears once per month. A site is overdue once that date passes without a completed audit.

Credential Vault

What it is

A separate, encrypted store for device and site credentials (usernames, passwords, PINs, URLs). Open it from Home → Credentials — it runs as its own service, so it has its own session.

Adding a credential to a device

  1. Go to Devices and open the device
  2. Click + Add Credential — the device comes preselected; leave the Device field set to that device so the credential is linked to it
  3. Enter Username, Password, URL / IP and any notes
  4. Enter the Master Password (see below) and click Save — you are returned to the device and the credential is listed

If the master password is wrong the form comes back with an error and keeps what you typed — nothing is saved until it is correct.

Revealing a saved password

Open a credential and click Show — you are prompted for the Master Password, then the value is revealed; Copy puts it on the clipboard. Every reveal is written to the vault's Audit Log.

Master password

Required to encrypt when saving and to decrypt when viewing. It is held in the server configuration (not in the app or the database) — ask your SimplyICT administrator if you don't have it. Keep it safe: it is the only key to the stored credentials.
