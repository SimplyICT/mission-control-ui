2026-09-17 (SOC P1.1): Agent auto-update shipped and verified. Server publishes one artifact via /api/agent/download/agent with X-Agent-Version/X-Agent-Sha256; the version+hash are parsed from agent_unified.py (soc_api.agent_meta(), mtime-cached) so a release is a one-line AGENT_VERSION bump. Registration ack now sends download_url (built from the host the agent reached), sha256 and a semver needs_update; the agent verifies sha+version, syntax-compiles, backs up to agent.py.bak, os.replace()s atomically, reports {"type":"update"} and re-execs — one attempt per process. Two long-standing bugs found while testing: (1) main() sat above six @handler definitions, so eventlog/forward_logs/self_update/fim_scan/packages/vuln_packages never registered when the agent ran as a script (server-pushed commands — including every queued FIM/vuln scan — were silently ignored); the __main__ guard now lives at the end of the file. (2) the on-connect update path referenced _aiohttp/_json, which only exist when aiohttp is MISSING, so every agent raised NameError and skipped the update — that was the real "chicken-and-egg". Outbox: delivered commands are marked 'sent' (no more 5s re-send spam) and unanswered ones are re-delivered on reconnect. Fleet note: agents below 1.1.1 cannot self-update (bug 1 + bug 2 live in their code) — they need one installer push; verified end-to-end locally with a 1.1.0-stamped agent that updated itself to 1.1.1 and reconnected.
