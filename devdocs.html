Developer Documentation

Architecture, API reference, and deployment notes

Architecture

The Audit Centre runs on a dedicated server (208.87.135.185) behind Cloudflare Access. Stack:

  • Frontend: Static HTML + vanilla JS served by nginx
  • API: FastAPI (device_audit_api.py) on port 8096
  • Database: Supabase (PostgreSQL)
  • Auth: Cookie-based sessions with tenant isolation

Audit Schedule

Per-site audit cadence, surfaced on audit-schedule.html and the dashboard tiles (#stat-next, #stat-overdue).

sites.audit_schedule_enabled  boolean  default true
sites.audit_weekday           smallint 0=Mon .. 6=Sun
sites.audit_frequency_months  integer  default 1
sites.next_audit_override     date     manual pin (nullable)
sites.audit_colour            text     hex accent for the centre

Next due = last completed audit + audit_frequency_months, moved forward to audit_weekday but clamped inside that month (_snap_to_weekday_in_month) so every centre appears once a month. Sites with no audit yet start from today. next_audit_override wins when set. Status: overdue / due (today) / upcoming.

Current cadences: Benowa, Benowa Hills, Riversdale — monthly on Saturday; Currumbin — monthly on Tuesday.

Credential Vault

Separate service alongside the audit platform — credential-system.service on .185, uvicorn on 127.0.0.1:5001, fronted by nginx at /credentials/ (prefix stripped, so the app serves /sites, /devices, /new, /{id}/decrypt, …).

DB          /home/aiagent/credential-system/vault.db (SQLite, tables: users, sites, devices,
            credentials, audit_logs)
Models      Credential(username, encrypted_password, url_ip, notes, device_id, site_id, user_id)
Endpoints   POST /new                    create credential (form: username, password,
                                        master_password, site_id, device_id, url_ip, notes)
            GET  /new?device_id=N&site_id=M  form with that device/site preselected
            POST /{id}/decrypt          form: master_password -> {"password": "..."} (403 if wrong)
            POST /{id}/edit|delete
Crypto      PBKDF2-HMAC-SHA256 (200k iters, per-user salt + ENCRYPTION_PEPPER) -> Fernet

Master password: validated by verify_master_password() — accepts VAULT_MASTER_PASSWORD (set in /etc/systemd/system/credential-system.service.d/10-vault-master-password.conf) or the user's own password. Required for both saving and revealing; the same value derives the encryption key.

Rotating it: python3 scripts/rotate_master_password.py --old OLD --new NEW re-encrypts every credential (dry-run with --dry-run), then update the drop-in, systemctl daemon-reload && systemctl restart credential-system.service.

Reveal flow: the credential page's Show button prompts for the master password and POSTs it to /{id}/decrypt (self-contained JS — the vault base template loads no JS libraries). Every reveal writes a DECRYPT row to audit_logs.

Known gap: the service still signs its JWTs with the default secret_key (no SECRET_KEY in its environment) — set one before relying on vault session isolation.

Database

Supabase tables:

  • tenants — Organisations
  • tenant_users — Login credentials
  • sites — Locations (tenant_id scoped)
  • devices — Device inventory
  • device_audits — Audit batches
  • audit_entries — Per-device audit results
  • remediation_actions — Remediation tracking
  • incidents — Incident register

Design Standard

The UI design standard is documented at DESIGN_STANDARD.md in each project root.

Key rules:

  • Background: #060608, accent: #FF6B00 (orange), font: Inter
  • Sticky rounded header with orange brand logo and Home button
  • Cards: dark translucent, subtle borders, 14px radius
  • Stat cards: gradient colored borders, floating orbs, colored values
  • Buttons: dark ghost with orange hover, primary solid orange
  • Tables: dark headers, uppercase labels, subtle row borders
  • Forms: dark inputs with orange focus
